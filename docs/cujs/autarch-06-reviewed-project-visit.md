# autarch-06-reviewed-project-visit

Design status: accepted direction, September 9, 2026.
Implementation and live validation: pending.
Persona: [experienced product leader](../personas.md).
Source: [human ratification](../decisions/2026-09-09-human-ratification.md).

Trigger: return to a project to choose one meaningful outcome and prepare its
implementation without rebuilding context from earlier conversations.

1. Enter from the estate overview and open Autarch's project workbench. Read
   accepted intent, current work, relevant evidence and a reasoned next-outcome
   recommendation.
2. Explore one multiple-choice question at a time. Correct an answer in free
   text and see the next question adapt. Existing evidence comes before new
   foundations; concrete comparisons help discover taste.
3. Switch between outcome/decision and map views. Selection and conversation
   remain intact. Choose purpose-to-work or theme layout, with pace across both.
4. Inspect a coherent synthesis: affected guidance and priorities, exact human
   wording, rationale, uncertainty, sources and superseded rulings. Explicitly
   accept that revision; see canonical persistence succeed or a precise block.
5. Request plan preparation. Observe Clavain's planning and independent review,
   budgets, artifact references and evidence. Prototype interaction questions
   that could change the plan. The plan includes scope, dependencies, checks,
   experience examples and retest criteria.
6. Leave during preparation, restart the controller, and resume the same visit.
   Reissue expired runtime questions with their history; retain corrections and
   prior plan attempts.
7. Finish with one independently reviewed implementation plan matching the
   accepted guidance. Other gaps stay visible. Starting implementation is a
   separate explicit action, not the result of finishing the visit.

Recognition condition: the human and the next runtime can explain what the
chosen outcome delivers, why it matters, which rulings constrain it and how it
will be checked, from the reviewed plan and its sources.

Failure paths: missing sources, stale revisions, conflicting rulings, unknown
project context, insufficient budget, unavailable provider or reviewer, failed
writes and uncertain worker liveness remain visible and recoverable. No failure
silently ratifies guidance or starts implementation.

Acceptance evidence must come from the exact signed build operating on a named
clean main checkout for the Autarch pilot, with explicit pinned Clavain and
Lattice build sources. Preserve the current installation, shortcuts and retained
evidence. Provider-context approval and recording permission are separate. Real
human acceptance is not replaced by test fixtures; record usability judgment
separately from automated checks.
