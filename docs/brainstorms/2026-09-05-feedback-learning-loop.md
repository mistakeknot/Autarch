# Feedback and learning loop: accepted rulings

Source: the user's implementation request, “Autarch: a complete feedback and
learning loop”. This synthesis advances the pilot beyond the earlier
[open dialogue](../research/2026-09-05-foundation-sprint-questions.md). It does
not backdate answers or claim that the live journey has been validated.

Autarch is a continuing project collaborator. Its own TUI is the workbench:
artifacts, proposals, progress, decisions, and a Flere conversation remain
visible there, in Cozy and Compact. A native companion shows selected evidence.
Files remain project truth; agents propose and the human rules. Clavain owns
execution policy and Intercore owns execution records.

The human selects a test window and explicitly starts recording. The full
session stays local until deleted, with recording status, storage usage and
pause/stop controls. Quick typed or spoken feedback preserves original voice,
editable transcript, timestamp, screenshot and available application context.
Microphone activation is limited to explicit voice notes. Capture and saving
work without agents, transcription, richer diagnostics or history services.

Flere investigates in the background while testing continues. Investigation
can read, research and propose; it cannot implement. Clarification waits for
review. Proposals are grouped by outcome and retain original observations,
evidence, uncertainty and reasoned disagreement. Acceptance covers the exact
immediate change and enduring guidance shown together, including scope and
rationale. Accepted work enters Clavain unless priority or dependencies defer it.

Retest presents the original feedback, a short checklist and a concrete build.
The verdict belongs to that build. A later related attempt must apply accepted
guidance without a reminder; evidence may still challenge the guidance.

One visible project conversation spans runtime/model changes. Show transferred
context and links to original sessions; tool execution state is not portable.
Present the next structured design question immediately after each answer.
External-session questions retain their original-session answering flow.
Outside review, consequential questions blocking relevant active work notify
the human; other questions collect in the project decision queue.

Foundation discovery includes project files, Git and relevant Alwe history.
Recovered rulings require evidence; inferred exceptions stay provisional.
Inherit shared guidance with explicit project exceptions. Resolve decisions
affecting the next slice, one question at a time, and expose other gaps.

Reuse Interweave's SQLite `lattice`, identity/crosswalk, relationships and query
infrastructure. The first graph capability is a rebuildable feedback trace:
review moment → feedback → accepted proposal/guidance → Beads work →
execution/build → retest verdict. Use an isolated projection. Human approval
is distinct from identity confidence. Preserve provenance, revisions, proposed
relationships, supersession and deleted/unavailable evidence. Complete Beads
relationship ingestion. Broader roadmap/cross-project analysis and Ultan
migration are later increments, not prerequisites or substituted scope.

Pilot: Autarch itself, on macOS 26, launched/configured through Autarch without
capture CLI arguments. Ad hoc feedback infers its destination; uncertain
routing saves an intake item with suggested project. This last choice remains
an explicit implementation assumption, not dispatch authority.

Alignment: closes the evidence, human ruling, execution and learning cycle.
Conflict/Risk: device quality and the actual human journey require live proof;
API imports and passing component suites do not provide that proof.
