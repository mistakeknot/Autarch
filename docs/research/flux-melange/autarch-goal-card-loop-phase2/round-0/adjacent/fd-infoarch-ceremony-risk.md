## Findings

### done-when-has-no-falsification-condition-for-its-own-premise
- **Severity:** P0
- **Where:** Proposal's own closing question ("is a per-project why-card the right instrument for overwhelm across 82 projects, or ceremony added to an estate that already has 2270 plans nobody reads") against the full DONE WHEN list.
- **What:** Every clause in DONE WHEN is checkable by an artifact or a mechanical observation: `card-check.py` exits 0, the gate is observed permitting/refusing from a live session, the confirm-cost and format findings are written down, the TUI renders 21 sessions with a coverage fraction, ranking matches ruling 11, four row states are visibly distinct, suites are green and mutations dead. None of these can come back false if the instrument is ceremony — the goal is scoped so that it succeeds by its own definition the moment the build works, independent of whether mk's overwhelm moved at all.
- **Evidence:** The goal text itself poses the premise question in its own voice ("that is the question one real card raises and the five drafted ones could not... is cheaper now than after the TUI reads it") — showing the author is aware this is a real open question — but then DONE WHEN contains zero clauses referencing overwhelm, revisiting, remembering, or any behavioral outcome for mk. Search the DONE WHEN text for "overwhelm," "revisit," "remember," "use," or "actually" — none appear; every verb is "renders," "exits," "matches," "observed permitting."
- **Suggestion:** Add one falsifiable DONE WHEN clause that could fail on the premise, not just on the build — for example: "mk, using the confirmed card and the TUI row together, reports whether they'd have found/remembered/ranked `unc-rancher` differently than before" or "the format-findings writeup states explicitly whether the six fields felt like the right instrument or like ceremony, and that answer is recorded as a ruling, not assumed." Without this, the goal cannot fail on the axis it claims to be testing.

### why-md-is-an-eighth-artifact-type-over-fields-prds-already-answer-at-low-rates
- **Severity:** P1
- **Where:** Brainstorm's diagnosis paragraph: *"Checked fairly against PRD contents rather than directory names — of 375 unique PRDs, 14% state a success metric, 5% a pain point, 2% a CUJ, 1% a persona, 0.3% a guardrail."* Estate inventory in the same paragraph: 2,270 plans, 831 brainstorms, 388 PRDs, 126 CUJs, 36 decision records, 3 personas, 0 metrics documents — seven named artifact categories, `docs/why.md` an eighth.
- **What:** The brainstorm's diagnosis is framed as "a request-shape failure, not a discipline failure: agents were never asked for a why." But the PRD compliance numbers show agents *were* asked (14% of PRDs do state a success metric, 5% a pain point) and mostly didn't answer — which is a different failure mode than "never asked," and one a new required file doesn't obviously fix. The estate already has 388 PRDs and 126 CUJs partially carrying this exact content; the proposal adds a ninth-field new file type with its own gate and validator rather than testing the cheaper alternative of surfacing the already-answered 14%/5%/2%/1%/0.3% directly in the switcher row, or raising compliance on the artifact types that already exist.
- **Evidence:** No comparison to "read from existing PRD/CUJ frontmatter instead of authoring a new file" appears anywhere in the brainstorm's Key Decisions table or the proposal. Decision 4 in the brainstorm ("Where the why lives — in-repo files, with a derived index") settles *storage location* but never argues against reusing an existing artifact type as the source of that index.
- **Suggestion:** Name the alternative explicitly and say why it loses: e.g. "PRD/CUJ fields are inconsistently located (title-only vs. frontmatter vs. prose) and a derived index over 388 files of unknown shape is a harder parsing problem than one new file with a fixed schema" would be a legitimate answer — but it should be stated as a ruling with a reason, the same standard the proposal already applies to the confirm-step cost and the format findings, rather than left implicit.

### uncrancher-is-a-best-case-pilot-selection
- **Severity:** P2
- **Where:** Proposal: *"Start with `unc-rancher`: it is a real GSV games-slate item, so its card is also the funding page's sales copy, which is the coupling this design rests on."* Measurement table: `uncrancher` drafts 4/6 fields (tied best in the 5-repo sample with `ravenous`), has 18 plans and 7 CUJs (second-richest of the five repos measured, behind only `shadow-work`'s 455/13).
- **What:** The stated reason for choosing `unc-rancher` (validate the funding-page coupling) is a real and legitimate reason, but it is also a project simultaneously selected for being well-documented (CUJs exist to draft `persona`/`pain`/`cuj`/`line` from) and externally incentivized to look good (a stranger reads this card as sales copy). Both properties push the pilot toward a best-case outcome on exactly the dimensions the goal wants to generalize from (confirm cost, format adequacy). `backfilling cards beyond the one confirmed` is explicitly OUT, so no second, less-favorable data point is planned before the format findings and confirm-cost rulings get written.
- **Evidence:** Cross-referencing the measurement table against the proposal's stated selection criterion confirms the double selection: the criterion named (funding coupling) is real, but it happens to coincide with (not be independent of) the criterion that would matter for generalization (material richness).
- **Suggestion:** When writing the format findings and confirm-cost rulings, name this selection explicitly — e.g. "measured on the second-richest of five sampled repos, chosen for external stakes; expect thinner projects (jawnomicon-shaped) to cost more and yield fewer draftable fields" — so the ruling carries its own scope rather than reading as estate-general.

### card-coverage-across-82-projects-has-no-stated-fraction-requirement
- **Severity:** P2
- **Where:** Proposal DONE WHEN: *"the TUI renders all 21 sessions as project rows with a stated coverage fraction"* — session coverage only. Contrast with the proposal's own stated principle two sentences earlier: *"Coverage is stated as a fraction with every unresolvable session named, never dropped — intermux reports 1 of 21 and discloses no gap, which is the failure this row is replacing."*
- **What:** The proposal explicitly names "silently dropping coverage information" as the failure mode the new row exists to fix — but applies that discipline only to session enumeration (21 sessions), not to card coverage across the 82-project estate the goal is actually about. After this goal ships, the TUI could legitimately render 82 project rows where 81 show `strength.score: 0/6` with no aggregate statement anywhere ("1 of 82 projects has a confirmed card") — the same kind of silent, undisclosed gap the proposal is explicitly trying to stop repeating, just on the axis (card coverage, not session coverage) that this particular goal is actually about.
- **Evidence:** DONE WHEN's four other bullets are all scoped to the one confirmed card and the 21-session TUI render; nothing requires the TUI (or the confirm-cost writeup) to state "82 projects, 1 confirmed" as a headline number the way "1 of 21" is named as the problem being fixed.
- **Suggestion:** Add a DONE WHEN clause requiring the TUI (or the format-findings writeup) to state the card-coverage fraction across all 82 projects explicitly, mirroring the session-coverage discipline the proposal already commits to. Cheap to add now, since the number is `1/82` regardless — the point is making the estate's real state visible rather than implicitly deferring it to phase 3 or never.

## Verdict
The goal is well-instrumented for proving the mechanism works — gate fires, validator exits cleanly, TUI renders states — but not instrumented at all for proving the mechanism matters: no DONE WHEN clause can fail if a confirmed card and a ranked row leave mk exactly as overwhelmed as before, and the one data point being generalized from is drawn from the best-documented, most externally-incentivized project in the sample. Both are cheap to correct by adding falsifiable clauses and naming the selection bias in the rulings that get written — before, not after, ruling 12's 82x commitment leans on them.
