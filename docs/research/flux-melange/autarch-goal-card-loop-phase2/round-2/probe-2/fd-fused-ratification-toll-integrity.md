# fd-fused-ratification-toll-integrity — round 2

## Findings Index
- [P1] override-cost-blind-spot — DONE WHEN prices only the expensive confirm-path branch, leaving the near-free override branch (the one 81 other repos will likely take) unmeasured and uncompared (§DONE WHEN / override) 
- [P1] format-finding-invalidates-own-mark — the "format finding" step this goal explicitly invites can silently flip unc-rancher's just-confirmed card to INVALID via the hard-pinned `card_version` check, with no re-ratification cost budgeted and no version stamp to grandfather it (§"are these the right six fields?" / card_version)
- [P1] provisional-erases-fatigue-and-misattributes-it — a fatigued, multi-session, partially-ratified confirm collapses into the same `provisional` state as an untouched draft, and the gate's own denial text asserts an unverifiable "drafted by an agent" story over that state (§DONE WHEN cost clause / guard-plan-needs-card.sh WHY strings)

## Findings

### override-cost-blind-spot
- **Severity**: P1
- **Where**: proposal DONE WHEN, "the confirm-step cost ... [is] written into the brainstorm as rulings with reasons" (2026-08-13-goal-card-loop-phase2.md lines 50-53); `guard-plan-needs-card.sh` lines 86-91 (override block) vs lines 100-104 (proper path: draft + confirm)
- **What**: The gate offers two paths to a permitted plan write: the proper path (draft `docs/why.md`, run the drafter, get mk to confirm — the exact session this goal is about to price on unc-rancher) and the override path (`AUTARCH_CARD_OVERRIDE="reason" <retry>`, costing one shell-quoted sentence, logged but never refused as long as the reason is non-empty). DONE WHEN commits to writing "the confirm-step cost" into the brainstorm as a ruling backing ruling 12's 82-repo rollout — but it names only the expensive branch. Nothing in DONE WHEN requires reading the override log (`log_line "OVERRIDE ..."` at line 87) alongside the confirm minutes. A cost lens alone would flag this as "n=1, unmeasured comparison condition" — routine extrapolation-risk language. An integrity lens alone would flag the override as a zero-cost evasion route around the gate. Neither alone explains why this specific omission matters *for what the goal is about to certify*: ruling 12's 82x commitment is a claim about the *proper-path* cost recurring 82 times, but the mechanism that actually governs load on the other 81 repos — especially the thin, unfunded, no-CUJ ones fd-hci-ratification-cost's own P0 already predicts will be worst-cased — is whichever path is cheaper at the point of friction, and the override will almost always win that comparison. The brainstorm ruling this goal produces will describe a workflow (confirm-then-permit) that the estate's actual future behavior will mostly route around, and the goal has no clause that would catch that gap.
- **Evidence**: `guard-plan-needs-card.sh:86-91` (override accepted with only a non-empty reason string, `exit 0`); `guard-plan-needs-card.sh:100-104` (proper path listed as option 1, requires draft + "ask mk to confirm it"); proposal lines 50-53 (DONE WHEN's sole cost clause names only "the confirm-step cost").
- **Suggestion**: In the confirm-step cost writeup, also pull and report the override log's entry count/reasons from the same measurement window, and state explicitly that the recorded minutes describe the proper-path branch only, not the blended real-world cost across both branches.

### format-finding-invalidates-own-mark
- **Severity**: P1
- **Where**: proposal lines 34-37 ("are these the right six fields? ... that is a format finding and it is cheaper now than after the TUI reads it"); `card-check.py:118-121` (`card_version != 1` is a hard `CardError`); `card-check.py` has no per-card field recording which schema version a `confirmed` status was struck against.
- **What**: The goal doesn't just risk a format finding — it explicitly solicits one from the unc-rancher confirm session and treats getting one as validating the process ("cheaper now than after the TUI reads it"). But `card_version` is checked with strict equality against `1`, and nothing in the card schema records which version a `confirmed` mark was ratified under. If the format finding this goal invites leads to the natural response — bumping `card_version` to 2 to admit the new/changed field — then the very next `card-check.py` run against unc-rancher's freshly-confirmed card (line 118-121) raises `CardError` and the verdict flips from `CONFIRMED` (exit 0) straight to `INVALID` (exit 2), which `guard-plan-needs-card.sh`'s case statement (line 79) turns into a hard `BLOCKED`. A cost lens alone would note "no one priced re-confirming"; an integrity lens alone would note "no version stamp to know what a mark was tested against" (both are already in the parent lenses' own material). What requires both together is the causal chain: the goal's *own success condition* on one DONE WHEN clause (a format finding, recorded as a ruling) can retroactively void its *other* DONE WHEN clause (a confirmed card that exits 0) with zero budgeted cost and zero recorded version to know it happened deliberately rather than by rot — the two halves of this goal's own completion criteria are not jointly satisfiable across time, and the proposal treats the format-finding branch as pure upside.
- **Evidence**: `card-check.py:118-121`; `guard-plan-needs-card.sh:76-82` (case 0 vs case 2 branches on exit code alone, no distinction for "was confirmed, now stale"); proposal lines 34-37 and DONE WHEN line 50 ("a confirmed `docs/why.md` that `card-check.py` exits 0 on").
- **Suggestion**: Either scope this goal's "format finding" outcome to record-only (explicitly defer any `card_version` bump to a separate goal, and say so), or add a migration/grandfather rule (e.g., a `confirmed_against_version` field, or a version check that warns rather than hard-fails on stale-but-previously-confirmed cards) before mk spends the confirm session this goal is measuring.

### provisional-erases-fatigue-and-misattributes-it
- **Severity**: P1
- **Where**: `card-check.py:126` (`status` is only ever `"provisional"` or `"confirmed"` — no third state); `guard-plan-needs-card.sh:78` (`WHY="... is PROVISIONAL (drafted by an agent, not yet confirmed by mk)"`); proposal DONE WHEN cost clause (lines 50-53).
- **What**: A card mk opens, drafts personally, and gets 45 minutes into declining four of six fields with real reasons before an interruption ends the session — leaving it `status: provisional` because `confirmed_at`/`confirmed_by` were never set (R3, `card-check.py:198-209`) — is stored identically to a card an agent drafted and nobody has ever opened. Both produce exit 1. Both trigger the exact same gate text at line 78, which additionally asserts "(drafted by an agent, not yet confirmed by mk)" — a claim card-check.py has no way to verify, since nothing in the schema records who drafted a field, only its `state`. A pure cost-lens reading would flag "fatigue's cheapest legal exit is to stop mid-session" as an ergonomics risk in isolation; a pure integrity-lens reading would flag "provisional doesn't distinguish refused from not-yet-reached" as a semantics gap in isolation. What needs both: the *mechanism* that produces the ambiguous state is a cost phenomenon (interrupted, resumed, or abandoned confirm sessions — the realistic shape of "on first touch" work per ruling 12, not the single uninterrupted sitting the pilot is likely to be run as), and the *consequence* is an integrity failure with a very specific, checkable shape — a user-facing message that confidently narrates an unverified authorship claim onto a state that could equally represent mk's own stalled effort. This also undermines the goal's own cost-recording DONE WHEN clause: with only one `confirmed_at` timestamp and no per-session log, a fragmented real-world confirm (start, interrupt, resume) leaves no data to reconstruct actual elapsed effort-minutes versus wall-clock time, so the number written into the brainstorm as a ruling is unauditable after the fact.
- **Evidence**: `card-check.py:126` (`STATES = ("drafted", "declined", "confirmed")` per field, but card-level `status` is a two-value enum); `card-check.py:198-209` (R3: confirmed requires no drafted field remaining, plus `confirmed_by`/`confirmed_at`, but no interim/partial timestamp); `guard-plan-needs-card.sh:78`.
- **Suggestion**: Reword the exit-1 `WHY` string to not assert authorship ("is PROVISIONAL — not yet confirmed by mk" is sufficient and true regardless of who drafted it), and have the confirm-step cost measurement log wall-clock start/stop across any interruption, not just a single elapsed-minutes estimate from one sitting.

## Verdict
All three findings sit precisely where the fused charter requires: a cost fact (which branch gets taken under time or fatigue pressure) that changes what a specific exit code or field is trusted to certify. None is recoverable by either parent working alone — each needed the cost mechanism to explain *why* the gap gets exercised and the integrity mechanism to say *what* silently breaks when it does. The format-version finding is the most consequential: it means this goal's two DONE WHEN clauses are not jointly stable over time, and the proposal should say what happens to unc-rancher's mark if its own encouraged format finding lands.
