## Root Cause Analysis

The structural tests serve as a drift detection mechanism -- they enforce that hardcoded counts in tests, PRD, README, and catalog all stay synchronized with the actual filesystem. The drift accumulated because:

1. **Component extraction** -- Skills and commands were extracted from Clavain to companion plugins (interspect, intertrust, etc.) over multiple releases, but test assertions were not updated at extraction time.
2. **Catalog staleness** -- The `gen-catalog.py` script had already been run and produced correct output, but the results were never committed.
3. **Missing documentation sections** -- The sprint discovery section was specified in tests (added when the discovery feature was built) but never added to sprint.md.

## Prevention

The `test_catalog_is_fresh` test is the primary guard -- it runs `gen-catalog.py --check` which validates all count strings across all documentation files. When components are added/removed, running `python3 scripts/gen-catalog.py` regenerates everything. The remaining tests (count assertions in test_agents/skills/commands) are redundant with the catalog check but provide clearer error messages for specific component types.

Recommendation: After any component addition/removal, always run:
```bash
python3 scripts/gen-catalog.py
python3 -m pytest tests/structural/ -v
```
